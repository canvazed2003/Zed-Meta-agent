# Telegram Business personal assistant

A bot that connects to **your own Telegram account** through Telegram Business ("Chatbots") and drafts
replies to people who write to you — in your name and in your style, based on `profile.md`.

Replies are generated by the **Claude Code CLI** (`claude -p`) installed next to the bot, so your Claude
**subscription** is used. An Anthropic API key is never used.

## What it does

- Someone writes to you → the bot reads the last messages of that chat, asks Claude for a reply in your
  style and in their language (Uzbek in the same script, Russian or English).
- **Preview mode is the default** (`AUTO_SEND=false`): replies are only printed in the logs
  (`PREVIEW, not sent`) and saved to `data/previews.jsonl`. Nothing is sent until you set `AUTO_SEND=true`.
- **Which chats the bot sees is decided by Telegram only**: *Settings → Telegram Business → Chatbots* in
  your Telegram app. There is no allowlist in the code.

### Behaviour

| Situation | What happens |
|---|---|
| Business connection of another account | Ignored (logged as a warning); Claude is never called |
| Which chats | Whatever you selected in *Telegram Business → Chatbots*; every chat Telegram delivers gets a reply |
| You write in a chat yourself | Saved to the history, never answered; the bot stays quiet in that chat for `OWNER_TAKEOVER_MINUTES` (default 15) |
| Messages from bots / sent by this bot | Ignored (the bot never answers its own replies) |
| The same update delivered twice | Handled once, also after a restart (`data/seen.json`) |
| Service messages (title changes, pins, ...) | Ignored; stickers, voice, photos etc. are described as `[sticker] 😀`, `[voice message]`, ... |
| `/pause` | Nothing is drafted or sent until `/resume`; survives restarts |
| Subscription usage limit | No new Claude calls until the reset time (or `LIMIT_COOLDOWN_MINUTES`); survives restarts; in auto-send mode you get one message |
| Timeout / login error | Logged; nothing goes to the chat; in auto-send mode you get a message at most every 10 minutes |
| Claude answers `[SKIP]` | Nothing is shown or sent ("ok", stickers, finished conversations) |
| Before auto-sending | The bot checks again that you did not write meanwhile, and re-asks Telegram (not the cache) that the connection is yours, enabled and allowed to reply |

### Commands (only in your private chat with the bot, only from `OWNER_ID`)

- `/start` — a guide in Uzbek: current mode and state, how to connect, the commands.
  Anyone else gets only a short Uzbek note that this is a personal assistant and they should write to the
  owner directly (no profile data, Claude is not called).
- `/pause`, `/resume` (also clears the limit and takeover timers), `/status`.
- Everything else written to the bot directly is ignored silently.

## How Claude is called

One process per reply, without a shell:

```
claude -p --safe-mode --settings '{"disableAllHooks": true, "enabledPlugins": {...: false}}' \
  --tools "" --strict-mcp-config --setting-sources "" --disable-slash-commands \
  --no-session-persistence --system-prompt-file <0600 temp file> --output-format json --effort low
```

- The conversation goes in on **stdin only**; the system prompt with your profile is in a 0600 temp file
  in `data/claude-run` (0700) that is deleted right after, so neither shows up in `ps`.
- No tools, MCP servers, plugins (every built-in plugin is switched off), skills, hooks, CLAUDE.md or
  auto-memory. The process runs in its own process group and is killed with all its children on timeout.
- **`--bare` is not used**: it ignores the OAuth login, so the subscription would not work.
- The child environment is scrubbed: every `ANTHROPIC_*` variable, `TELEGRAM_BOT_TOKEN`,
  `CLAUDE_CODE_USE_BEDROCK/VERTEX/FOUNDRY`, `CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_SIMPLE` are
  removed; `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` and `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` are added.
- **Token rules**: `CLAUDE_CODE_OAUTH_TOKEN` is a `claude setup-token` token (`sk-ant-oat...`). It is passed
  only in the child's environment, never in argv, stdin or the prompt, and it is replaced by `[REDACTED]` in
  any CLI output before parsing. API keys (`sk-ant-api...`) are rejected. If the token is rejected, the error
  says to run `claude setup-token` again and shows `CLI said: ...` (with the token hidden).
- `python bot.py --check-claude` sends one tiny request and fails unless tools, MCP servers, plugins and
  skills are all empty and no API key is used.

## Deploy to Railway

1. On a computer with a browser run `claude setup-token`, log in with your subscription account and copy
   the `sk-ant-oat...` token (valid for 1 year).
2. In @BotFather: `/newbot`, then *Bot Settings → Business Mode* → turn on. Get your numeric id from @userinfobot.
3. Create a **private** GitHub repository and push this code (`profile.md` is baked into the Docker image).
4. Railway → *New Project* → *GitHub Repository* → pick the repository. It builds with the `Dockerfile`.
5. Service → *Variables* → *Raw Editor*:
   ```
   TELEGRAM_BOT_TOKEN=...
   OWNER_ID=...
   CLAUDE_CODE_OAUTH_TOKEN=sk-ant-oat...
   AUTO_SEND=false
   ```
   Optional: `CLAUDE_MODEL`, `CLAUDE_EFFORT`, `CLAUDE_TIMEOUT_SECONDS`, `LIMIT_COOLDOWN_MINUTES`,
   `OWNER_TAKEOVER_MINUTES`, `HISTORY_LIMIT`. Do not set `CLAUDE_BIN`, `DATA_DIR` or `PROFILE_PATH`.
6. Volume: right-click the canvas (or Cmd+K / Ctrl+K) → *Volume* → choose the service → mount path exactly
   **`/app/data`** → *Deploy*. Without a volume, history, pause and limit state are lost on every deploy.
7. Logs should show `Bot @... is running`, `Mode: PREVIEW` and
   `Claude auth: subscription token from environment variables`. Red lines in Railway just mean stderr, not errors.
8. Send `/start` to the bot. Then in Telegram: *Settings → Telegram Business → Chatbots* (needs Telegram
   Premium) → enter the bot's username → choose which chats it may see → allow replying.
   The log shows `Business connection ...: user=<id> enabled=True`.
9. When someone writes to you, a `PREVIEW, not sent` block appears in the logs. When the replies look good,
   set `AUTO_SEND=true`.

Notes:

- Run the bot in **one place only**: two pollers with the same bot token disturb each other (do not run
  `python bot.py` locally while Railway runs it).
- Every push redeploys. Changing `profile.md` also means commit + push.
- Claude token expired or leaked: run `claude setup-token` again and update the Railway variable.
  Bot token leaked: `/revoke` in @BotFather and update `TELEGRAM_BOT_TOKEN`.

## Local development

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt     # Windows: .venv\Scripts\pip
cp .env.example .env && chmod 600 .env
```

Put the `claude setup-token` token into `.env` (`CLAUDE_CODE_OAUTH_TOKEN=`, one line, with an editor).
If you leave it empty, this machine's own `claude` login is used.

```bash
python bot.py --check-claude
python bot.py --try "Salom, qalesan?"
```

Locally settings come **only** from `.env`; variables in your shell are ignored.

### Commands and exit codes

| Command | What it does | Exit codes |
|---|---|---|
| `python bot.py` | Run the bot with `.env` | 0 stopped, 2 config error or bot token rejected |
| `python bot.py --settings-from-env` | Container mode: settings from environment variables, which are then removed from the process environment | same |
| `python bot.py --check-claude` | Check the Claude CLI setup (no Telegram settings needed) | 0 ok, 1 problem, 2 config error |
| `python bot.py --try "text"` | Draft a reply to a made-up message (no Telegram) | 0 ok, 1 Claude error, 2 config error |

`--check-claude` and `--try` also work together with `--settings-from-env`.

### Tests

```bash
.venv/bin/python -m pytest
```

All tests run offline: a recording fake Telegram session, a real aiogram `Dispatcher`, and a fake `claude`
executable. On Windows the POSIX file-mode tests are skipped.
